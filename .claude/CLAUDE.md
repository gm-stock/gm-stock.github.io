# GM 재고관리 (젠틀몬스터 소품·집기 재고)

에이도스 스튜디오가 운영하는 젠틀몬스터 국내외 매장용 소품·집기 재고관리 웹앱.
사용자는 비개발자(대표 1인)이므로 설명은 쉬운 한국어로, 변경은 작고 확인 가능하게 한다.

## 구조

| 파일 | 역할 |
| --- | --- |
| `index.html` | 매장 매니저 화면(재고 조회, 출고 요청). 다국어 지원 |
| `admin/index.html` | 관리자 화면(재고 관리, 주문 승인·반려·출고, 시트 동기화) |
| `sw.js` | 서비스워커. 네트워크 우선, 실패 시 캐시 |
| `manifest.json`, `manifest-admin.json` | PWA 설정(매장용·관리자용) |
| `icons/` | PWA 아이콘 |

- 빌드 도구 없음. HTML 파일 하나에 CSS·JS가 모두 들어 있는 단일 파일 구조.
- 호스팅: GitHub Pages, `main` 브랜치가 곧 배포본. `main`에 머지되면 바로 실서비스에 반영된다.
- 외부 라이브러리: Firebase JS SDK 10.12.0(app, firestore, auth), SheetJS(xlsx) 0.18.5 — CDN 로드.
- 이 저장소와 `tb-stock/tb-stock.github.io`(템버린즈)는 거의 같은 구조의 쌍둥이 앱이다.
  한쪽의 버그 수정이나 기능은 다른 쪽에도 필요한지 사용자에게 확인한다.

## 데이터 (Firebase 프로젝트 `gm-stock-management`)

| 컬렉션 | 내용 |
| --- | --- |
| `items` | 재고 품목(이름, 이미지 URL, 수량 등) |
| `orders` | 매장 출고 요청. `storeName`, `items`, `status`, `handledAt`, `rejectReason`, `cancelReason`, `canceledAt` |
| `stockLogs` | 재고 변동 기록(관리자 화면에서 기록) |
| `shipments` | 시즌 배송 내역. `title`, `openDate`, `open`(접수 열림), `stores`{매장명: [{itemId, itemName, optName, collection, qty}]} |
| `claims` | 배송 이슈 접수. `shipmentId`, `storeName`, `itemId`, `itemName`, `optName`, `type`(파손·불량·누락), `reason`, `qty`, `shipped`, `photos`, `reporter`, `status` |

- 주문 상태 값은 한국어 문자열이다: `검토중`, `승인`, `준비중`, `출고대기`, `출고완료`, `반려`, `취소`.
  영어로 바꾸지 않는다(기존 데이터와 깨짐).
- `STOCK_HELD`(검토중~출고완료) 상태의 주문은 재고를 점유한다. 반려·취소 시 재고가 복원된다.
  상태 전환 로직을 바꿀 때는 재고 증감이 맞는지 반드시 확인한다.
- Google Sheets 동기화는 Apps Script 웹앱 URL로 호출한다(`admin/index.html` 안). URL은 바꾸지 않는다.
- 매장 목록 자동완성: `STORE_LIST` 배열(`index.html`, `admin/index.html` 양쪽에 있음)이 기본 목록이고,
  관리자 '시즌 배송 → 매장 목록 관리'에서 추가한 매장·엑셀 이름(별칭)은 `storeNames` 컬렉션(`name`, `aliases`)에 저장돼 화면에서 합쳐진다.
  시즌 등록 엑셀의 매장명은 기본 목록 → 별칭 순으로 맞춘다. 기본 목록은 2026-10-28 사용자가 준 매장 목록 엑셀(100곳)로 교체했고,
  엑셀 이름이 매장명과 다른 곳은 `admin/index.html`의 `STORE_ALIASES`에 있다. 기존 주문에 저장된 옛 매장명은 바꾸지 않았다.
- `admins`, `stores` 컬렉션은 아래 '로그인·권한' 참고.
- 배송 이슈 상태 값(한국어): `검토중`, `재발송 예정`, `재발송 완료`, `반려`. `재발송 예정`으로 바뀔 때 재고 차감,
  재발송 예정·완료 → 검토중·반려로 되돌리면 복원. 접수 기한 = 오픈일 + 7일(그날 밤 12시, 한국 시간).
  재요청 수량은 배송 수량보다 많아도 접수할 수 있다(2026-10-28 사용자 요청으로 제한 해제).
- 매장 화면 '배송 이슈' 탭은 접수가 열린(`open:true`) 시즌이 있을 때만 눌린다. 시즌 등록은 관리자 '시즌 배송' 탭(최고관리자).
- 시즌 배송·배송 이슈의 구글 시트 기록: `apps-script/season_claims_sync.gs`(출고 내역 시트에 붙인 추가 파일, 5분마다 갱신).

## 로그인·권한 (2026-10 도입)

- Firebase Auth 이메일/비밀번호 로그인. 관리자 화면과 매장 화면 모두 로그인해야 데이터가 보인다.
- `admins` 컬렉션: 문서 ID = 관리자 이메일(소문자), 필드 `role`이 `owner`(최고관리자) 또는 `manager`(담당자).
  - 담당자는 조회·출력·주문 처리만 가능. 상품 추가·이름/수량/사진 변경, 일괄 발주, 주문 삭제는 최고관리자만
    (`html.role-manager` CSS로 숨기고, 함수 단계에서도 한 번 더 막는다).
- `stores` 컬렉션: 문서 ID = 매장 공용 계정 이메일. 매장 화면은 아이디만 입력하면 `@eidosstudio.co.kr`을 붙인다.
- 보안 규칙 원본과 테스트는 `firebase/` 폴더(기록용). 게시는 Firebase 콘솔에서 한다.
  매장 계정은 재고 수량만 바꿀 수 있고, 외부인은 읽기·쓰기 모두 막혀 있다.
- Google Sheets 동기화(Apps Script)는 API 키가 아니라 `ScriptApp.getOAuthToken()`(datastore 범위)으로 Firestore를 호출한다.

## 디자인 (2026-10 리디자인)

- 색은 CSS 변수로 관리한다: `--bg #f7f6f3`, `--surface`, `--ink #111`, `--sub`, `--muted`, `--line`, `--low #b3001b`(재고 부족),
  `--accent #c2410c`(주요 버튼·검토중), `--ok`/`--ok-bg`(출고완료). 어두운 화면 값은 `body.dark`에 따로 있다.
- 새 화면 요소에는 파란·보라 같은 색을 직접 쓰지 말고 위 변수를 쓴다. 모서리는 각지게(`border-radius:0`).
- 글꼴: Roboto + 나눔고딕(Google Fonts), 일본어·중국어는 Pretendard로 대체 표시.
- 기본은 밝은 화면, 선택한 밝기는 localStorage `gm-theme`에 저장(매장·관리자 공통). 헤더는 밝기와 상관없이 항상 검정.
- 상품 카드의 컬렉션 색: `index.html`의 `COLL_COLORS`(구글 시트 Apps Script 색과 같은 계열).
- PC(가로 1100px 이상) 매장 화면은 장바구니가 오른쪽에 항상 보인다.
- 출고 지시서 인쇄 창(`printOrder`)과 사진 확대 창(`viewPhoto`)은 별도 창이라 CSS 변수를 쓰지 않는다.

- 화면 구성은 2026-10-21 사용자가 최종 승인한 시연판(Claude 아티팩트 'GM 재고 시연')을 따른다: 매장은 브랜드 헤더·물결 띠·검색·[재고|출고요청] 탭·옵션 선택 상자 카드·PC 3단 배치·휴대폰 주황 출고 요청 띠, 관리자는 위쪽 탭(주문 관리 먼저)·요약 숫자 4칸·상태 칩·주문 표·재고 표. 색만이 아니라 배치까지 시연판과 같아야 한다.

## 다국어 (`index.html`)

- `I18N` 객체에 언어별 문구가 있다: `ko`, `en`, `ja`, `zh-CN`, `zh-TW`.
- 선택 언어는 localStorage `gm-lang`에 저장된다.
- **번역하지 않는 것(원문 유지)**: 상품명, 매장명, 컬렉션명, 소재.
- 새 문구를 추가할 때는 5개 언어 모두에 키를 추가한다. 누락되면 해당 언어에서 빈칸이나 키 이름이 보인다.
- 번역 문구는 먼저 표로 보여주고 사용자가 확인한 뒤 코드에 반영한다.

## 작업 규칙 (반드시 지킬 것)

1. 수정 전에 무엇을, 어디를, 왜 바꾸는지 계획을 먼저 보여주고 승인받는다.
2. 큰 수정은 한 번에 하지 말고 단계로 나눈다. 한 단계 = 한 가지 변경.
3. 매 단계 후 문법 검증을 실행한다:
   `python3 .claude/scripts/check-html.py index.html admin/index.html && node --check sw.js`
4. 요청 범위 밖의 코드는 정리·리팩터링하지 않는다.
5. Firestore 컬렉션 이름, 필드 이름, 상태 값을 바꾸는 변경은 반드시 먼저 물어본다.
6. 변경은 `claude/`로 시작하는 브랜치에 올리고 PR로 제안한다. `main`에 직접 푸시하지 않는다.
7. 화면에 보이는 변경이면 PR 설명에 확인 방법(어느 화면에서 무엇을 눌러보면 되는지)을 적는다.

## 알려진 사항

- 서비스워커 캐시 때문에 배포 후 옛 화면이 보일 수 있다. 큰 변경 시 `sw.js`의 `CACHE_NAME` 버전을 올린다(현재 `gm-stock-v4`).
- 사용자는 2026-10-21부터 "보안상 꼭 본인이 해야 하는 것만 빼고 PR 머지까지 직접 처리"하도록 맡겼다. 단계별 PR·검증 규칙은 그대로 지킨다.
